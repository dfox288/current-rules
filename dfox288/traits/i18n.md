# Trait: `i18n`

Your repo has locale files (`i18n/locales/`, or the equivalent under its package directory).

## Rules

- **[contract item]** Every product-facing string ships in both locales (English and German today) in the same
  commit — never one locale ahead of the other. *Check: reviewer diffs the locale files for the commit; your repo's
  own locale parity test, if it has one (its `CLAUDE.md` names it), is the mechanical gate.*
- **[contract item]** No hard-coded product-facing text in a component or template — it goes through the i18n
  key, even for a string that "will never need translating." *Check: reviewer greps new/changed template code for
  literal user-facing strings outside an i18n call.*

## What this trait does not cover

Internal log lines, code comments, commit messages, and developer-facing error text stay in English regardless
of this trait — this only covers what a user of the product reads.
